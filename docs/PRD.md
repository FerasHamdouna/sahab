# سحاب (Sahab) — وثيقة متطلبات المنتج (PRD)

> **الإصدار:** 0.2 · **التاريخ:** 2026-10-26 · **الحالة:** القرارات الأساسية محسومة — جاهز لمرحلة UI/UX

---

## 1. الفكرة باختصار

موقع طقس بسيط في وظيفته، **مبهر في شكله**. المستخدم يبحث عن مدينة، فيرجع له طقسها الحالي وتوقعات 24 ساعة و7 أيام — وكل هذا فوق **خلفية ثلاثية الأبعاد (3D) حيّة تتحول فوراً لتعكس طقس تلك المدينة**: شمس، غيوم، مطر، ثلج، ضباب، عاصفة، ليل أو نهار.

**الجملة اللي تلخص المنتج:**
> "بتكتب اسم المدينة… وبتحس إنك واقف فيها."

---

## 2. المشكلة والفرصة

- مواقع الطقس الحالية إما مزدحمة بالإعلانات والأرقام، أو مملة بصرياً (أيقونة شمس صغيرة ورقم).
- الطقس تجربة **حسية** — المطر صوت وحركة، الحر ضوء ووهج — لكن المواقع تعرضه كجدول.
- **الفرصة:** تجربة بصرية غامرة وسريعة، تعطي المعلومة الأساسية بلمحة وتخلي المستخدم يرجع لأنها ممتعة.

## 5. المتطلبات الوظيفية

### F1 — البحث عن مدينة
- حقل بحث واحد بارز في أعلى الصفحة.
- **إكمال تلقائي (Autocomplete)** بعد حرفين، مع debounce ≈ 250ms.
- كل اقتراح يعرض: اسم المدينة، المنطقة/المحافظة، الدولة (+ علم الدولة).
- البحث يدعم **العربية والإنجليزية** ("عمان" و "Amman").
- تنقل كامل بالكيبورد (↑ ↓ Enter Esc).
- حفظ **آخر 5 عمليات بحث** محلياً (localStorage) وعرضها عند التركيز على الحقل الفارغ.

### F1b — موقعي (طقس مكاني)
المستخدم يقدر يعرف طقس مكانه بدون ما يبحث، بطريقتين:

1. **تحديد تلقائي (GPS / Geolocation):**
   - زر **"موقعي"** 📍 دائم الظهور جنب حقل البحث.
   - بالضغط عليه: المتصفح يطلب الإذن ← نجيب الإحداثيات ← نحوّلها لاسم مدينة (reverse geocoding) ← نعرض طقسها.
   - حالات: جاري التحديد (spinner على الزر)، رفض الإذن (رسالة لطيفة + اقتراح الطريقة الثانية)، فشل/انتهاء المهلة (8 ثوانٍ).
2. **اختيار يدوي:** إذا رفض الإذن أو بدّه مدينة ثانية — يبحث عن مدينته ويضغط **"اجعلها مدينتي"** ⭐.

**"مدينتي" (Home):**
- تُحفظ محلياً. **كل ما يفتح الموقع يفتح مباشرة على مدينته** — بدون بحث وبدون انتظار.
- إذا كان مختار التحديد التلقائي، نحدّث الموقع بهدوء بالخلفية عند كل زيارة (بدون ما نطلب الإذن مرة ثانية).
- يقدر يرجع لمدينته بضغطة من أي مكان (زر 📍 / ⭐).

**أول زيارة (Onboarding):**
- المشهد 3D يظهر فوراً على مدينة افتراضية (تقدير تقريبي من المنطقة الزمنية للمتصفح) — **الصفحة ما تكون فاضية أبداً**.
- بطاقة صغيرة غير مزعجة: **"بدك تشوف طقس مكانك؟"** [استخدم موقعي] [اختار مدينتي] [لاحقاً].
- **لا نطلب إذن الموقع تلقائياً** عند الفتح — فقط عندما يضغط المستخدم (أفضل ممارسة، ونسبة قبول أعلى).

### F2 — الطقس الحالي
| الحقل | مثال | ملاحظات |
|-------|------|---------|
| درجة الحرارة | **24°** | العنصر الأكبر في الصفحة |
| وصف بكلمة/كلمتين | "غائم جزئياً" | مشتق من رمز WMO |
| أيقونة الحالة | ⛅ | متحركة بشكل خفيف |
| الإحساس الحراري (Feels like) | 26° | ثانوي |
| العليا / الدنيا لليوم | 28° / 17° | ثانوي |
| اسم المدينة + الوقت المحلي فيها | عمّان · 14:32 | الوقت المحلي مهم للمشهد (ليل/نهار) |

### F3 — الرياح والرطوبة
- **الرياح:** السرعة (كم/س) + **الاتجاه** (سهم يدور + نص "شمالية غربية") + الهبّات إن وجدت.
- **الرطوبة:** نسبة مئوية + مؤشر بصري (شريط/دائرة).
- الرياح **تؤثر على المشهد 3D** (سرعة الغيوم، ميلان المطر، حركة الجزيئات).

### F4 — توقعات 24 ساعة القادمة
- شريط أفقي قابل للتمرير (أو منحنى) يبدأ من **الساعة الحالية**.
- كل ساعة: الوقت، أيقونة، الحرارة، احتمال الهطول (إذا > 0%).
- منحنى حرارة ناعم يربط النقاط.
- تمييز بصري لشروق/غروب الشمس إذا وقعا ضمن الـ 24 ساعة.

### F5 — توقعات 7 أيام
- قائمة 7 صفوف: اسم اليوم ("اليوم"، "غداً"، ثم أسماء الأيام)، أيقونة، احتمال الهطول، العليا والدنيا.
- **شريط نطاق حرارة** لكل يوم (مثل iOS) مقارن بمدى الأسبوع كله.

### F6 — الخلفية ثلاثية الأبعاد (قلب المنتج)
- مشهد 3D واحد **مستمر لا يُعاد تحميله أبداً** — فقط تتغير معاملاته.
- يتغير حسب: **حالة الطقس**، **ليل/نهار** (حسب التوقيت المحلي للمدينة وشروق/غروب الشمس)، **قوة الرياح**، **درجة الحرارة** (تدرج لوني دافئ/بارد).
- انتقال سلس بين المشاهد (≈ 1.2–2 ثانية) بدون قفزات أو شاشة سوداء.
- تفاصيل كل مشهد في [SCENES.md](SCENES.md).

### F7 — الإعدادات البسيطة
- تبديل الوحدات: **°C / °F** و **كم/س / ميل/س** (يُحفظ محلياً).
- اللغة: **العربية (RTL) افتراضياً**، مع زر تبديل للإنجليزية (LTR). تُحفظ محلياً.
- احترام إعداد **Reduce Motion** في النظام (مشهد هادئ بدون جزيئات كثيفة).

### F9 — الأصوات المحيطة
- أصوات تتبع الطقس: مطر (خفيف/غزير)، رياح (حسب السرعة)، رعد (متزامن مع البرق)، عصافير/هدوء للصافي نهاراً، صراصير ليل للصافي ليلاً.
- **شغّالة افتراضياً.** زر كتم/تشغيل ظاهر دائماً، والاختيار يُحفظ محلياً.
- **قيد المتصفحات:** المتصفح ما بيسمح بتشغيل صوت قبل أول تفاعل. الصوت يبدأ مع **أول تفاعل** (نقرة، كتابة في البحث، لمس) بـ fade-in ناعم. ونعرض أيقونة الصوت بحالة "جاهز" لحد ما يصير التفاعل.
- الانتقال بين الأصوات = **crossfade** بنفس مدة انتقال المشهد.
- الصوت يتوقف (fade-out) إذا التبويب صار مخفي.
- الأصوات **لا تؤخر** المشهد ولا البيانات: تُحمّل بعد ظهور المشهد، بأولوية منخفضة.

### F8 — الحالات الخاصة
| الحالة | السلوك |
|--------|--------|
| تحميل | Skeleton للبطاقات، **المشهد السابق يبقى ظاهر** (لا شاشة فاضية) |
| مدينة غير موجودة | رسالة لطيفة داخل قائمة الاقتراحات |
| فشل الشبكة / API | رسالة + زر إعادة المحاولة، آخر بيانات ناجحة تبقى معروضة |
| WebGL غير مدعوم | خلفية متدرجة (CSS gradient) + صورة ثابتة حسب الطقس |
| جهاز ضعيف | خفض الجودة تلقائياً (DPR، عدد الجزيئات، إطفاء post-processing) |

## 6. المتطلبات غير الوظيفية

### الأداء — "ما في delay في الخلفية"
هذا أهم متطلب تقني. الأرقام المستهدفة:

| المقياس | الهدف |
|---------|-------|
| معدل الإطارات — ديسكتوب | **60fps ثابت** |
| معدل الإطارات — جوال متوسط | **≥ 30fps** |
| بدء انتقال المشهد بعد وصول البيانات | **< 100ms** |
| مدة الانتقال بين مشهدين | 1.2–2s، سلس، بدون stutter |
| أول ظهور للمشهد 3D (4G) | < 2.5s |
| LCP (أول محتوى رئيسي) | < 2.0s |
| حجم JS الأولي (gzipped) | < 350KB للـ 3D + التطبيق |
| أصول المشهد (textures/models) | < 1.5MB إجمالي، **إجرائية (procedural) قدر الإمكان** |
| Frame drop أثناء تبديل الطقس | **صفر** إطار > 50ms |

**المبادئ اللي تضمن ذلك** (التفاصيل في [TECH_STACK.md](TECH_STACK.md)):
1. Canvas واحد يُنشأ مرة واحدة ولا يُفك أبداً (never unmount).
2. كل الـ shaders والمواد تُجمّع (compile) **عند التحميل الأول** وليس عند أول مرة يظهر فيها المطر.
3. تغيير الطقس = تغيير **أرقام** (uniforms) بشكل تدريجي، ليس إضافة/حذف كائنات.
4. الجزيئات (مطر/ثلج) عبر **InstancedMesh** أو GPU particles — آلاف الجزيئات في draw call واحد.
5. لا تحديث React state داخل حلقة الرسم (useFrame) — refs فقط.
6. **Prefetch**: عند تمرير الماوس/التركيز على اقتراح مدينة، نجلب بياناتها مسبقاً.

### الوصولية (Accessibility)
- تباين نص ≥ 4.5:1 فوق كل المشاهد (طبقة glass/blur خلف البطاقات).
- كل المعلومات متاحة نصياً لقارئات الشاشة — المشهد 3D زخرفي (`aria-hidden`).
- `prefers-reduced-motion` مدعوم.

### التوافق
- آخر نسختين من Chrome, Safari, Firefox, Edge — ديسكتوب وموبايل.
- عرض من 360px إلى 2560px.

### الخصوصية
- لا تتبع، لا حسابات. الموقع الجغرافي يُطلب فقط عند الضغط على "موقعي".

## 7. مصدر البيانات

**المقترح: [Open-Meteo](https://open-meteo.com)**
- مجاني، **بدون مفتاح API**، بدون تسجيل.
- يوفر: Geocoding (بحث المدن بالعربي والإنجليزي)، الطقس الحالي، توقعات بالساعة، توقعات يومية، شروق/غروب، `is_day`.
- يستخدم رموز **WMO** القياسية لحالة الطقس — نربطها مباشرة بالمشاهد.
- **ملاحظة ترخيص:** الاستخدام المجاني لغير التجاري. إذا صار المشروع تجارياً نحتاج خطة مدفوعة أو مزوّد آخر (الباك إند سيعزل هذا القرار).

**مرحلة الفرونت إند:** بيانات وهمية (mock fixtures) لكل حالة طقس + خيار الاتصال المباشر بـ Open-Meteo للتجربة الحقيقية.
**مرحلة الباك إند:** الباك إند يصير الوسيط (proxy) — يوحّد شكل البيانات، يخزّن مؤقتاً (cache)، ويسمح بتبديل المزوّد لاحقاً. شكل البيانات الموحد محدد في [API_CONTRACT.md](API_CONTRACT.md) **من الآن** حتى ما نعيد كتابة الفرونت.

```
فتح الموقع
   │
   ├─► المشهد 3D يظهر فوراً (مدينة افتراضية/آخر مدينة)
   │
   ▼
يكتب "دب..."  ──►  اقتراحات: دبي، دبلن، ...
   │                  │
   │                  └─ hover على "دبي" ← prefetch للبيانات بالخلفية
   ▼
يختار "دبي"
   │
   ├─► البطاقات: skeleton لحظي (أو فوري إذا prefetch اكتمل)
   ├─► المشهد: يبدأ الانتقال من "مطر عمّان" إلى "شمس دبي الحارقة" (< 100ms)
   ▼
يقرأ: 38° · مشمس · رياح 12 كم/س · رطوبة 45%
   │
   ▼
يمرر للأسفل: 24 ساعة ← 7 أيام
```
